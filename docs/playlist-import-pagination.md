# 歌单导入分页检查（2026-09-11）

## 责任边界

平台 URL、请求、分页、游标和详情分批只在插件实现。客户端调用
`importMusicSheet`，校验/去重、展示与保存结果，不增加平台 API 兜底。
`worksNum` 是来源总数，`musicList.length` 是实际取得条数，不保证二者相同。
分页失败应抛出错误，避免把部分列表作为完整导入交付。

## 检查结果

| 插件 | 修改与覆盖 |
| --- | --- |
| QQ | 导入每次请求 500 个来源位置，按总数继续；短页不提前终止；保序去重；重复页/中途空页/请求错误报错。远程详情每次 100 个位置。 |
| 酷我 | 修复 `page < totalPage` 丢失最后一页；未知总数继续到短页；旧接口错误向上传递；切换接口时重置全部分页状态。 |
| 酷狗 | global collection 短页但未到总数时继续；详情失败不跳过；分享码预览不足时按页获取；详情每批最多 200 条。 |
| Bilibili | 收藏夹按 `has_more` 获取超过 100 页；重复页和停滞报错；普通详情仍只取当前页。 |
| 汽水 | 跟随 `next_cursor`；首请求失败保留插件已有网页路径，后续请求失败报错而非退回首批。 |
| 咪咕 | 保留按页发现 CID；检测重复/空页；详情每批 100 条，避免超长 URL；保留 VIP 歌曲元数据，播放权限仍由上游决定。 |
| 网易云 | 已按完整 `trackIds` 每批 200 首读取，无客户端 999 限制；增加导入严格错误传递，保留其他调用兼容行为。 |

异常请求保护阈值会报错，不会静默截断后返回成功。

## 验证

- `node --test tests/playlist-import.test.cjs`：确定性响应覆盖七个平台的大列表、末页和停滞条件。
- 客户端 Rust/QuickJS 实际加载更新后的 QQ 插件，导入 `2784566436`：
  返回「我喜欢」，来源标注 1929 首，保序去重后 1916 首，末首 ID `1512907`。
  QQ 在连续请求中返回的来源总数存在波动；不将 1929 宣称为实际取得条数。
- 其他平台本次以模拟响应回归为主，不宣称七个平台都已完成真实账号端到端验证。
- 汽水已有网页路径只暴露页面提供的资源，没有新增猜测的网页分页 API。

上线后需要用户更新本地插件；仅更新 Flutter APK 不会替换已安装的插件脚本。
